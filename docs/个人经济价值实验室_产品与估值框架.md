# 个人经济价值实验室：产品与估值框架（v0.1）

**定位**：一个面向中国用户的、私密且可解释的个人财务教育工具。它借用 DCF 的思维，估算未来经济现金流的现值，帮助用户做职业、储蓄、保险、负债和再学习决策。

**不是**：人的真实价格、可交易市值、信用评分、雇佣筛选、婚恋匹配、放贷依据，或任何对人格与社会价值的评价。

---

## 1. 核心判断：可以折现“经济现金流”，不能给“人”定价

企业估值的对象是企业可分配现金流；人不是企业，也不存在可被交易、被收购的“股权”。因此，产品不应输出“某人值多少钱”，而应输出一个带有边界条件的财务估算：

> 在一组由用户确认的职业、收入、支出、资产、负债、退休和风险假设下，未来可持续经济盈余折现到今天的区间是多少？

这一定义把模型的用途从评价人，转为理解选择。一个照顾家人、做公共服务、从事创作或暂时没有收入的人，绝不因模型数字较低而“价值较低”；模型未试图衡量这些重要但不可货币化的价值。

### 1.1 三个互补结果，而非一个“市值”

| 结果 | 定义 | 用户可以用来回答什么 | 不能代表什么 |
| --- | --- | --- | --- |
| **人力资本现值 HCV** | 未来劳动/经营所得的税后、职业维护成本后的现值 | 我的赚钱能力对家庭安全的贡献有多大？ | 人格、能力全貌或可出售价值 |
| **资产负债净额 NAV** | 用户当前可计量资产的审慎价值减去负债 | 我的已积累安全垫是多少？ | 未来劳动收入 |
| **个人经济净值 PEV** | `HCV + NAV`，并单列不确定性 | 在当前假设下，我的经济安全底座大约在什么区间？ | 可交易的“市场价值” |

最重要的设计原则是**不重复计价**：若某套房、基金或企业股权已经按市场/估值计入 NAV，就不能再把它未来产生的租金、利息、分红或经营现金流完整折现一次。

## 2. 把企业 DCF 迁移到个人：保留什么，改造什么

参考 DCF 的四个纪律，但必须改写其经济含义。

| 企业 DCF 概念 | 个人模型的对应物 | 产品解释 |
| --- | --- | --- |
| FCFF | 人力资本自由现金流 HCF | 税后劳动/自营收入，扣除维持收入能力的必要成本与基本生活支出 |
| D&A / CapEx | 职业维护与能力再投资 | 证书、培训、转岗、工具、迁居、健康维护等；并非所有消费都是“投资” |
| 营运资本变动 | 流动性缓冲变化 | 应急金、收入回款周期、必要保证金等对可用现金的占用 |
| WACC | 个人风险调整贴现率 | 无风险时间价值加上职业、行业、收入集中和健康/地区等风险调整 |
| 终值 TV | 有条件的持续现金流 | 仅适用于养老金、已拥有的可持续经营权益等；绝不默认劳动收入永续 |
| 三情景 | 压力测试 | 用悲观、基准、乐观路径看下行、常态与上行，而不是预测唯一答案 |

### 2.1 核心公式：先估人力资本，再合并资产负债表

显性预测期（建议按年，直到法定/自主退休年龄）的人力资本自由现金流：

```text
HCF_t = 税后劳动与自营收入_t
      − 基本生活与家庭刚性支出_t
      − 职业维护/再学习/健康维护投入_t
      − 收入获取的必要成本_t
      − 流动性缓冲增加_t
```

人力资本现值：

```text
HCV = Σ [HCF_t × 生存/就业概率_t ÷ (1 + r_t)^t] + PV(合格终期现金流)
```

个人经济净值：

```text
PEV = 审慎资产价值 − 有息负债 − 其他可确认义务 + HCV
```

其中 `r_t` 是风险调整贴现率。MVP 可先采用一个按情景固定的年化贴现率；后续版本才引入逐年风险曲线。输出必须同时展示**未折现累计现金流、折现率、终值占比、各项扣减**，让用户能够复算。

### 2.2 避免双重计量的资产处理规则

| 项目 | 推荐处理 | 不能同时做的事 |
| --- | --- | --- |
| 现金、存款、货币基金、上市证券 | 以审慎市值计入 NAV | 再把全部利息/分红作为 HCF 折现 |
| 自住住房 | 以用户选择的审慎净变现价值计入 NAV，或仅做居住成本情景 | 既计全额房价又计租金收益 |
| 出租房 | 二选一：净出售价值计入 NAV；或把净租金 DCF 后计入 | 市值和租金 DCF 双计 |
| 已持有企业股权 | 二选一：公允价值/交易估值；或经营现金流 DCF | 股权市值与企业现金流 DCF 双计 |
| 公积金、养老金权益 | 根据可支配性与规则分别列示，默认保守折扣 | 将不可自由动用权益当作随时可用现金 |
| 房贷、消费贷、信用贷 | 负债余额计入 NAV；利息在未来现金流中体现 | 既减去全额未来本息又减去当前本金余额 |

## 3. 中国语境下的关键建模选择

模型要承认中国用户的现实约束，而不是套用美国式收入曲线。

### 3.1 收入：用“可持续税后可得收入”，不是税前月薪

基础输入按月收集、按年计算：工资/奖金、个体经营净收入、副业净收入、社保与个税、收入回款稳定性。年终奖和佣金应拆成“确定部分”和“浮动部分”，浮动部分在悲观情景中应显著折扣。

用户可选择的职业收入类型：

- 固定薪酬：机关事业单位、国企、成熟企业职员等；
- 固定薪酬 + 绩效：大多数市场化岗位；
- 项目/佣金型：销售、自由职业、内容/咨询等；
- 自营/创业：按企业经营现金流而非营业额录入；
- 退休/半退休：养老金、年金、租金等合规、可持续收入；
- 暂无劳动收入：保留生活支出与资产负债的情景模拟，不把用户排除在外。

### 3.2 支出：明确“基本生活线”和“可选择消费”

不能用用户全部消费直接推断“价值”。MVP 把支出至少分为：

1. 基本生活与家庭刚性支出：居住、食品、医疗、抚养、赡养、必要通勤；
2. 职业维护：培训、资格、设备、必要迁居、求职、健康维护；
3. 自主选择消费：旅行、娱乐、升级消费等。

PEV 的核心口径使用前两类。结果页同时提供“维持当前生活方式”的可选口径，但不得暗示节省消费会提升一个人的人身价值。

### 3.3 社保、个税、退休与住房：参数化，绝不写死

这些规则具有城市差异与政策调整风险。小程序不应在前端硬编码全国统一税率、缴费基数、退休年龄或养老金替代率，而应：

- 首期让用户录入税后收入，减少计算错误；
- 可选开启“估算税社保”，并标注城市、年度和数据来源；
- 将退休年龄、养老金开始年份、养老金金额、房贷剩余期限设为用户可编辑参数；
- 对政策型现金流施加资格条件和情景折扣，默认不将预期中的不确定权益视作保证收入。

### 3.4 家庭口径必须由用户选择

个人、伴侣、家庭共享财务是三种完全不同的估值边界。首屏明确选择：

- **个人模式**：只计本人可支配收入、个人资产负债和本人承担的义务；
- **家庭共同模式**：要求录入共同资产、共同债务、抚养与赡养责任；
- **仅职业能力模式**：不计家庭支出和现有资产，只看未来职业现金流。

不得默认把伴侣收入或共同资产归属于单一用户。

## 4. 关于“公务员、程序员和有生息资产”的正确建模

### 4.1 公务员/稳定就业：稳定降低风险，不等于工资永续

稳定编制、较低失业概率、社保保障和相对平滑的收入曲线，主要通过以下变量体现：

- 较低的收入中断概率；
- 较窄的悲观情景收入跌幅；
- 较低但非零的职业风险溢价；
- 明确的退休年份后，劳动收入归零或降为退休金现金流。

不能因为工作稳定就将工资设为无期限永续增长。真正可能进入“持续现金流”的，通常是符合资格的养老金、已持有资产的收益权或可持续经营权益；它们也需按规则、期限和风险单独建模。

### 4.2 程序员/技术岗位：收入曲线更重要，终值不必存在

技术岗位常见特征是早中期收入增长较快、行业波动和技能淘汰风险较高、需要持续再学习。模型应允许：

- 前 5 年较高但逐步收敛的收入增速；
- 35/40/45 岁等用户自设节点的转管理、转产品、转自由职业或收入回落情景；
- 每年学习/工具/迁居成本作为职业再投资；
- 至退休年龄的有限现金流，而非人工设置“程序员永续增长”。

没有终值不是模型缺陷。**职业现金流有确定截止日，反而通常比虚构终值更诚实。**

### 4.3 有生息资产：先判断“本金是否已计入”

用户若已拥有股票、债券、房产或生意，资产本身是今天的价值，收益是未来现金流，两者不能相加两次。产品提供“资产法 / 收益法”二选一，并把选择展示在报告封面。

## 5. 增长、再投资与终值：继承 DCF 最重要的两条纪律

### 5.1 增长不是免费的

企业终值里有 `增长率 = 再投资率 × ROIC`；个人层面的对应关系可以写成：

```text
可持续收入增长 ≈ 能力再投资 × 能力资本回报
```

这里的能力再投资包括学习时间、培训费用、作品积累、健康、迁居与人脉投入；“能力资本回报”体现为收入提升、就业选择增加或失业期缩短。它并不适合机械计算，但产品应要求用户为收入增长填写一个可解释的来源，例如“完成执业资格”“转入更高附加值岗位”“经营获客系统成熟”。

若没有路径，长期高增长只能在乐观情景中出现，不能进入基准情景。

### 5.2 终值的准入门槛

终值在个人模型里很容易被滥用。MVP 使用“默认关闭，逐项开启”的规则：

| 现金流类型 | 是否允许终值 | 处理建议 |
| --- | --- | --- |
| 普通工资、绩效、项目收入 | 否 | 预测至退休/合同到期/职业转折点 |
| 已确认的养老金/年金 | 有限条件下允许 | 按开始时间、领取期限、资格与政策敏感性折现 |
| 已持有金融资产收益 | 通常不允许 | 若本金已进 NAV，收益不重复折现 |
| 可持续自营业务的可分配现金流 | 条件允许 | 必须与企业权益价值二选一，并披露经营、继任和再投资风险 |
| 知识产权/版权等长期收入 | 条件允许 | 设置期限、衰减率、平台和合同风险 |

若确有独立、可持续的终期现金流，可用保守戈登公式：

```text
TV = CF_(n+1) ÷ (r − g)
```

必须满足 `r > g`，且 `g` 不高于长期宏观名义增长的审慎假设；产品不提供“永远高增长”的滑杆。结果页必须高亮终值占比：若超过总值的 35%，提示用户检查假设；超过 50%，标为“高终值依赖，不宜作为决策依据”。

## 6. 风险调整：从一个固定折现率，走向可解释的风险曲线

### 6.1 MVP：三个场景、三个贴现率

用户不需要理解 CAPM 才能使用。MVP 通过职业稳定性、收入波动、技能可迁移性、单一雇主依赖、健康与家庭责任五个问题生成**可编辑建议区间**。

```text
个人风险调整贴现率 r
= 无风险时间价值
+ 行业/岗位中断风险溢价
+ 收入波动与集中度溢价
+ 地域、健康、负债压力等个体风险调整
− 合同保障、可迁移技能、足额应急金等缓释项
```

这是教育型风险刻画，不是金融产品收益率预测或授信评分。系统不应把职业、性别、婚育、户籍等敏感身份直接映射为风险分数。

### 6.2 三情景要“真有差异”

| 变量 | 悲观 Bear | 基准 Base | 乐观 Bull |
| --- | --- | --- | --- |
| 收入 | 行业承压/空窗期/奖金下滑 | 按可验证路径缓慢变化 | 晋升、转岗或业务增长兑现 |
| 职业再投资 | 转岗或补技能投入上升 | 维持计划投入 | 投入带来更高回报 |
| 必要支出 | 医疗、育儿、赡养或房贷压力上升 | 正常通胀与规划 | 支出效率改善 |
| 贴现率 | 更高 | 中性 | 更低但不为零 |
| 终期现金流 | 折扣、延后或不计 | 保守计入 | 条件改善后计入 |

推荐概率默认可用 25% / 50% / 25%，但必须允许修改并在报告中完整展示。最有价值的结果不是概率加权单点，而是悲观情景下的现金流缺口、应急金月数和可行动的缓释方案。

## 7. 产品体验：微信小程序 MVP

### 7.1 用户旅程

```text
免责声明与隐私选择
    → 选择估算边界（个人 / 家庭 / 职业能力）
    → 5 分钟基础问卷
    → 设置人生节点与三情景
    → 结果：区间 + 时间线 + 敏感性
    → “如果我进修/提前还贷/留足应急金会怎样？”模拟
    → 生成本地报告卡（默认不含金额分享）
```

### 7.2 MVP 页面与需求

| 页面 | 目标 | 核心内容 |
| --- | --- | --- |
| 欢迎与边界 | 建立正确预期 | 非定价声明、隐私说明、估算边界选择 |
| 基础信息 | 少输入、少敏感数据 | 年龄段、城市等级可选、职业收入类型、退休计划 |
| 收入与职业 | 建立有限期收入曲线 | 税后收入、奖金/副业、稳定性、未来节点、再学习投入 |
| 支出与责任 | 识别安全垫 | 基本支出、房贷/消费贷、抚养赡养、应急金 |
| 资产负债 | 计算 NAV，防止双计 | 资产类别、估值方式、债务余额与利率 |
| 情景编辑 | 让假设可见可改 | Bear/Base/Bull 收入、成本、贴现率、概率 |
| 结果报告 | 给出行动而非标签 | HCV/NAV/PEV 区间、现金流瀑布、终值占比、敏感性 |
| 行动实验室 | 把估值变成决策 | 进修、储蓄、还债、保险、转岗等“假设变化”对比 |

### 7.3 结果页的首屏文案（建议）

> 这不是你的“身价”。这是在你设定的假设下，未来经济现金流与已有资产的保守估算。真正值得关注的是：最坏情况下你能否承受、哪些变量最值得改善、下一步能做什么。

首屏展示顺序：

1. 悲观 / 基准 / 乐观的 **PEV 区间**，不突出单一数字；
2. 应急金可覆盖月数与未来三年可能现金流缺口；
3. HCV 与 NAV 构成，及终值占比；
4. 前三个敏感变量；
5. 可执行的行动建议（例如补足 6 个月应急金、降低高息债务、验证转岗收入假设）。

### 7.4 可视化建议

- **人生现金流时间线**：从现在到退休，按三情景画税后收入、必要支出和盈余；
- **价值构成条形图**：NAV 与各阶段 HCV 的组合，清晰区分资产现值和未来劳动；
- **敏感性矩阵**：收入增长 × 贴现率，显示区间而非精确金额；
- **风险雷达/清单**：收入集中、债务压力、应急金、技能可迁移性、终值依赖；
- **行动前后对比**：用户修改一项计划后，展示影响来源和不确定性。

不要做职业排行榜、城市身价榜、用户排名或“打败了多少人”。这类设计既无教育价值，也会把工具滑向比较、羞耻与歧视。

## 8. 数据、隐私与合规：产品的底线

财务、职业和家庭责任属于高度敏感信息。即使 MVP 仅作个人教育，也应从第一天按高标准设计。

### 8.1 数据最小化

- 默认本地计算、默认不上传；
- 不要求真实姓名、身份证号、银行卡、单位名称、精确住址；
- 收入、资产和债务都支持区间输入；
- 分享卡默认隐藏金额，只分享“我完成了一次人生现金流体检”；
- 云同步、报告导出、匿名统计均为单独、可撤回授权。

### 8.2 明确禁止的用途

- 不向雇主、招聘方、学校、房东、婚恋平台、保险或信贷机构输出数据或评分；
- 不提供“职业优劣”“人群排名”“配偶价值匹配”等功能；
- 不将结果用于个性化借贷、保险定价或投资推荐；
- 不诱导用户以隐私换取结果，也不允许社交分享页面暴露财务金额。

### 8.3 风险提示与人工复核

结果页固定提示：模型不是投资、税务、法律、保险或职业建议；涉及婚内财产、继承、重大债务、房产处置和养老金权益时，建议用户咨询持证/专业人士。上线前需针对适用的个人信息、算法、金融营销和小程序平台规则进行专业合规审查。

## 9. 计算引擎设计：可测试、可审计、可解释

产品的核心不是 UI，而是一个独立的纯计算模块。建议先定义如下结构。

```ts
type Scenario = 'bear' | 'base' | 'bull'

interface CashFlowYear {
  year: number
  afterTaxEarnedIncome: number
  essentialLivingCost: number
  careerInvestment: number
  incomeAcquisitionCost: number
  liquidityReserveChange: number
  employmentProbability: number // 0..1
  discountRate: number
}

interface Asset {
  category: 'cash' | 'marketableSecurity' | 'home' | 'rentalProperty' | 'businessEquity' | 'pensionOther'
  conservativeValue: number
  valuationMethod: 'nav' | 'dcf'
}

interface Liability {
  balance: number
  annualInterestCost?: number
  isIncludedInCashFlow: boolean
}
```

计算顺序：

1. 校验所有概率、贴现率、退休节点和终值条件；
2. 对每个年度计算 `HCF_t`；
3. 以就业/生存概率与折现率得到 `PV(HCF_t)`；
4. 只有通过终值准入规则的独立现金流才计算 TV；
5. 对资产按 `nav` / `dcf` 互斥计入；
6. 扣减当前负债余额，并检查未来现金流是否已重复扣减本金；
7. 输出三情景、概率加权值、敏感性和完整的计算解释。

### 9.1 必做校验规则

- `终值增长率 >= 贴现率`：阻止计算；
- 劳动收入预测超过退休/合同截止节点且无用户确认：提示修正；
- 已按 NAV 计入的资产又录入对应收益：阻止或要求二选一；
- 终值占比超过 35%：黄色提示；超过 50%：红色提示；
- 悲观情景比基准更乐观：提示检查；
- 概率之和不等于 100%：阻止报告生成；
- 家庭模式中共同资产归属未确认：不计算单人 PEV；
- 高息债务与不足三个月应急金并存：优先显示流动性风险，而非“价值数字”。

## 10. MVP 范围、非范围与迭代路线图

### Phase 0：研究与原型（1–2 周）

- 访谈 10–15 位不同收入类型的潜在用户，验证他们是否理解“经济价值”而非“人的价格”；
- 用匿名案例手算 6 组情景：稳定就业、技术岗位、自营者、已退休、有高杠杆房贷、家庭共同财务；
- 找财务规划、隐私与合规专业人士审阅口径；
- 输出可点击原型和计算公式测试样例。

### Phase 1：私密 MVP（3–5 周）

- 本地优先的微信小程序；
- 基础问卷、三情景、人力资本与 NAV、时间线和敏感性；
- 无账号体系、无排行榜、无网络爬取、无外部数据接入；
- 完整的假设说明、导出与清除本地数据功能。

### Phase 2：可解释增强（4–6 周）

- 城市/年度参数包（带来源与版本）；
- 人生事件模拟：育儿、转岗、进修、创业、提前还贷；
- 匿名、本地可选的基准对照，只展示区间和样本说明；
- 模型版本对比和报告快照。

### 明确不做（至少在 MVP）

- 信用评分、贷款或保险推荐；
- 基于职业/学历/城市的财富排名；
- 公开社区、炫耀式金额分享；
- 自动抓取银行卡、社保、公积金、券商或税务账户；
- AI 自动判定用户职业前景或生成唯一“正确”人生方案。

## 11. 需要验证的关键假设

| 假设 | 验证方式 | 成功信号 |
| --- | --- | --- |
| 用户接受“经济价值”表述 | 访谈与文案 A/B 测试 | 多数用户不将其理解为人格排名 |
| 用户愿意录入简化数据 | 5 分钟可用性测试 | 基础流程完成率高，资产负债跳失低 |
| 三情景能帮助决策 | 任务测试：进修 vs 提前还贷 vs 保留现金 | 用户能复述关键变量和下一步行动 |
| 隐私承诺足够可信 | 原型评审 | 用户理解本地计算和金额隐藏分享 |
| 结果不会诱发焦虑或羞耻 | 访谈与退出反馈 | 用户认为结果是导航而非判决书 |

## 12. 示例（仅说明公式，不代表任何职业结论）

假设某用户还有 20 年工作期。基准情景下未来第 1 年税后劳动收入为 24 万元，基本生活与家庭刚性支出 12 万元，职业维护投入 1.2 万元，必要收入获取成本 0.8 万元，当年 HCF 为 10 万元。此后收入和支出按用户可解释的路径变化，并对每年的职业持续概率与贴现率折现。

若其有 30 万元现金和基金、20 万元剩余有息债务，则当前 NAV 为 10 万元。若这些基金按 NAV 计入，就不把预期基金利息再放入 HCF。最终报告展示的是 HCV、NAV、PEV 三者及其悲观/基准/乐观区间，而不会说“这个人市值 X 万元”。

## 13. 一句话原则清单

1. 估的是现金流假设，不是人的价值。
2. 收入稳定性影响风险和概率，不等于无限期收入。
3. 增长需要能力再投资，不能凭空永续。
4. 有退休期限的劳动收入，通常不该有终值。
5. 资产价值和资产收益只能选一种口径，严禁双计。
6. 三情景和敏感性比一个精确数字更诚实。
7. 最坏情景的流动性与债务问题，优先于“估值变高”。
8. 所有金额、假设和数据都应由用户掌控、可见、可删。
