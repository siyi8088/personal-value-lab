# 个人经济价值实验室：双层产品实施方案（v1.0）

## 1. 这次调整要解决什么

原方案的建模完整，但首次用户需要理解资产、负债、家庭责任、三情景和现金流折现，才得到结果。它适合已经有明确财务管理需求的人，不适合作为微信分享进入的第一步。

新版把产品拆为两条连续但独立成立的路径：

```text
朋友分享 / 小程序搜索
        ↓
匿名「个人快速测」：3 分钟，少输入，立刻可分享
        ↓                         ↘
结果卡 + 一项行动建议              直接退出，数据仍只在本机
        ↓
用户主动点「做一份我的完整规划」
        ↓
微信登录并补充数据（分步保存）
        ↓
注册「财务实验室」：安全垫、资产负债、情景与完整报告
```

**核心结论**：简单版是面向每个人的独立产品，锚定“个人的未来职业收入潜力”；进阶版才处理“个人或家庭的完整财务安全与选择”。不应把登录、资产录入或复杂报告设为获得首次结果的前提。

### 1.1 两层产品的边界

| 维度 | 个人快速测（V1 首发） | 财务实验室（登录后进阶） |
| --- | --- | --- |
| 核心问题 | 未来 10 年，我的职业收入大致会怎样变化？ | 在收入、支出、资产和责任共同作用下，我的安全垫与选择空间如何？ |
| 估算对象 | 个人税后劳动/经营收入趋势 | 人力资本现金流 + 资产负债 + 家庭责任 |
| 典型耗时 | 2–3 分钟 | 首次 10–15 分钟，之后可持续更新 |
| 输入量 | 4 个必填 + 1 个可选 | 按模块渐进录入，不要求一次填完 |
| 身份 | 匿名，本地临时数据 | 微信登录；用户明确选择是否云同步 |
| 输出 | 收入区间、趋势类型、稳定性、一个行动建议、分享卡 | 安全垫、现金流缺口、三情景、行动模拟、私密报告 |
| 分享 | 默认隐藏金额，只分享趋势类型与完成状态 | 默认不可分享金额；可导出仅自己可见的报告 |
| 不做什么 | 不算净资产、负债、家庭，不给“身价” | 不做排名、征信、借贷/保险/投资推荐 |

### 1.2 对外文案与命名

不要把简单版称为“身价测试”或“个人估值”。首发页优先使用：

- 主标题：**看见你的未来收入地图**
- 副标题：用 3 分钟，了解未来十年职业收入的可能走势。
- 说明：这是一份基于你填写信息的教育性估算，不衡量人的价值，也不是财务、投资或职业建议。
- 进阶入口：**想继续看安全垫、房贷和转行选择？建立我的财务实验室。**

“个人经济价值实验室”保留作品牌名和进阶功能名；用户首次接触的是更具体、低心理负担的“未来收入地图”。

## 2. 简单版：可裂变的最小闭环

### 2.1 用户任务与成功标准

用户完成的不是“填写一张财务表”，而是：

> 我用很少的信息，看到了自己未来收入的保守、常规和向上可能，并带走一条明天能做的建议。

简单版首发验收目标：

| 指标 | 首发目标 | 定义 |
| --- | --- | --- |
| 开始后完成率 | ≥ 65% | 点击“开始”后到首次结果页的比例 |
| 中位完成时长 | ≤ 180 秒 | 排除后台停留时间 |
| 结果页分享点击率 | ≥ 15% | 不以实际转发数作为唯一指标 |
| 进阶意向率 | 10–25% | 结果页点击“建立财务实验室” |
| 输入放弃率 | 单页 < 12% | 用于发现问题过多或文案不清 |
| 误解率 | 可用性测试中 < 10% | 将其理解成“人的价格/职业排名”的用户占比 |

上线前不要承诺具体商业转化率；先用 20–30 位种子用户验证这些方向性指标和访谈反馈。

### 2.2 输入设计：4 必填 + 1 可选

所有货币输入均支持“约数”，不要求单位、公司、真实姓名、精确住址或资产明细。

| 顺序 | 字段 | 控件与选项 | 目的 | 必填 |
| --- | --- | --- | --- |
| 1 | 年龄段 | 18–24、25–29、30–34、35–39、40–49、50+ | 选择预测期和职业阶段默认值 | 是 |
| 2 | 税后月收入区间 | `<5k`、5–8k、8–12k、12–20k、20–35k、35k+；“我不方便说” | 估算起点；最后一项仍可给非金额结果 | 是 |
| 3 | 当前工作状态 | 稳定受雇、受雇+绩效、项目/自由职业、自营/创业、正在转型/待业 | 生成收入波动和中断的默认假设 | 是 |
| 4 | 已确认的短期变化 | 已有上行信号、暂无确定变化、已有压力、还说不清 | 只调整前两年，避免让主观乐观延续为十年增长 | 是 |
| 5 | 最想改善什么 | 涨薪、转行、稳定收入、学习技能、开始储蓄、暂时没有 | 决定结果中的一条行动建议 | 否 |

设计要求：

1. 每屏只出现一个问题，顶部显示 `1 / 5`，可返回修改。
2. 年龄、收入、职业状态为大按钮选项；避免首次使用键盘输入。
3. 用户点“我不方便说收入”时，结果页不显示金额区间，替换为收入趋势和稳定性结果；绝不因未填金额而卡住。
4. 第 4 题不问“你对自己有信心吗”，只问对客观收入变化的判断，避免把情绪转化为分数。
5. 输入页底部固定短说明：`数据仅保存在这台设备；无需登录即可查看结果。`

### 2.3 五个页面的精确流程

#### 页面 A：落地页 / 分享承接页

目标是让用户在 10 秒内理解价值和隐私边界。

内容顺序：

1. 标题“你的未来收入地图”；
2. 一张抽象的三条趋势线插画，不放财富、豪车、排名等暗示；
3. `3 分钟 · 不用登录 · 默认不保存到云端`；
4. 主按钮“开始看看”；
5. 文本链接“它是怎么算的？”打开简明规则弹窗；
6. 页底边界：`估算职业收入可能性，不给人定价，不用于任何征信或推荐。`

如果来自好友分享，落地页增加“朋友完成了一次未来收入地图”，仍不展示对方的金额、职业、年龄或结果标签。

#### 页面 B：快速问答

按 2.2 的五题逐屏展示。进度页不得包含注册或订阅引导。第五题完成后按钮文案为“生成我的地图”。

提交时立即把表单序列化到 `wx.setStorageSync` 的临时草稿中，再调用本地计算函数。计算不依赖网络；网络不可用时应与正常情况完全一致。

#### 页面 C：结果首屏

首屏只回答三个问题，不堆模型参数：

1. **未来十年税后职业收入可能范围**：悲观 / 常规 / 向上三个区间；选择“收入不方便说”的用户显示“低波动 / 有变化 / 需防波动”的趋势描述；
2. **收入路径类型**：如“稳步积累型”“成长突破型”“波动进攻型”“重建调整型”。这是解释性标签，不是高低优劣标签；
3. **一条此刻最有用的建议**：例如“先留出 3 个月基本开销，能让转型期的选择更从容”。

首屏固定免责声明：`这是依据少量自报信息生成的粗略范围，不预测你的能力或人生结果。`

按钮优先级：

- 主按钮：`看看我能做什么`（进入行动建议，不要求登录）；
- 次按钮：`生成不含金额的分享卡`；
- 文字按钮：`修改我的回答`。

不要在首屏自动弹出登录框，也不要用“解锁你的完整身价”制造焦虑。

#### 页面 D：行动建议

展示 2–3 张“下一步卡片”，仅有一张与用户选择的目标强关联。每张卡包含：为何适合、一个小动作、预计完成周期、一个“保存计划”按钮。

示例规则：

| 用户信号 | 建议卡 | 小动作 |
| --- | --- | --- |
| 项目/自由职业 + 收入不确定 | 建立收入缓冲 | 记录近 6 个月回款，先确定自己的低谷月收入 |
| 受雇 + 已确认短期上行 + 想涨薪 | 证明下一档能力 | 写下一个可量化成果，并约一次发展沟通 |
| 想转行或学习 | 用低成本验证方向 | 用两周完成一个作品/访谈，而非先投入昂贵课程 |
| 正在转型/待业 | 把现金流与求职分开规划 | 列出必要开销和可承受的求职周期 |
| 想开始储蓄 | 先建立自动化小缓冲 | 从下个发薪日设置固定金额转入独立账户 |

建议为教育内容，不可包含具体证券、贷款、保险产品或保证收益表述。

#### 页面 E：分享与自然进阶

分享卡的默认内容：

- 标题“我完成了一次未来收入地图”；
- 不带优劣的路径标签；
- 一句行动宣言，例如“我准备先验证一次转行方向”；
- 二维码/小程序路径及品牌；
- 可选的用户昵称，默认关闭；
- 明确不包含金额、年龄、收入、职业、位置和建议细节。

分享后回到结果页。在用户已看过结果和行动建议后，才显示软性进阶入口：

> 这张地图只看职业收入。补充支出、房贷、储蓄或家庭责任后，才能看见你的安全垫和具体选择空间。

按钮：`建立我的财务实验室（登录后可保存）`。进入前展示“为什么需要登录”说明，见 4.2。

### 2.4 简单版输出与算法

简单版不计算 NAV、PEV、完整 HCV 或“净值”。它计算的是一个明确命名为 **十年税后职业收入情景** 的近似范围。

#### 2.4.1 V1 输入到参数的映射

将收入区间转换为区间中点，并保留上下界。例如 8–12k 对应月收入基准 `[8,000, 12,000]`，而不是伪精确的 `10,000`。`35k+` 让用户在下一屏可选 `35–50k / 50–80k / 80k+`，否则收入区间会失真。

参数配置文件只存默认值，必须可版本化：

```ts
type WorkType = 'stable_employed' | 'employed_variable' | 'project' | 'business' | 'transition'
type Outlook = 'up' | 'steady' | 'uncertain'

interface QuickAssumption {
  downsideFactor: number                // 压力情景的收入折减，不代表长期预测
  stabilityLabel: string                // 面向用户的解释，不能只显示数值
}
```

初始值需在研究阶段通过案例和专业人士审阅校准，不能声称来自全国真实职业统计。V1 的长期基线一律是**按今天购买力大致维持**，不为任何职业类型默认添加收入增长率。稳定受雇、绩效岗位、自由职业、自营和转型期的差异只影响压力情景的区间宽度，而不是谁“必然增长更快”。

“未来 12–18 个月已确认的变化”只能来自已发生、已谈定或有合同支持的事实：已确认上行只在前两年形成有限提升；已有压力只在前两年形成有限下降；暂无确定变化和还说不清不改变收入。第 3 年起全部回归平稳基线。年龄只用于职业阶段的合理提示，不推断能力、健康、婚育或退休政策。

#### 2.4.2 计算方法

对每个情景 `s ∈ {bear, base, bull}` 和第 `t = 1..10` 年：

```text
income_t = income_(t-1) × (1 + confirmedChange_t) × downsideScenarioFactor_s
tenYearIncome_s = Σ income_t
```

其中：

- `confirmedChange_t` 只在前两年出现，且只在用户提供已确认事实时使用；第 3 年起为 0；
- `downsideScenarioFactor_s` 只在“有压力时”使用，用于体现不同工作方式下的波动暴露；
- 简单版默认只显示“有压力时”和“按当前底盘”。没有已确认上行时，第三行明确写“未来上行需要先验证”，而不是虚构乐观情景；
- 输出展示四舍五入的万级区间，例如 `约 80–105 万`，不显示小数和逐年精确工资；
- 若输入未含金额，跳过金额计算，输出只依据工作状态和展望的“趋势与稳定性说明”。

收入路径标签由“当前阶段 × 波动水平 × 已确认短期变化”映射，需保证每个标签都有中性说明：

| 标签 | 触发示例 | 用户解释 |
| --- | --- | --- |
| 稳步积累型 | 稳定受雇、稳定/上升 | 你的路径更依赖持续积累；关注下一档能力与缓冲。 |
| 成长突破型 | 受雇+绩效、上升、目标为涨薪/学习 | 上行机会存在；先验证能带来收入变化的关键能力。 |
| 波动进攻型 | 项目/自营 | 收入弹性较大；优先分清高峰收入与可持续收入。 |
| 短期变化已确认 | 已有上行事实 | 只把已经确定的变化计入前两年，之后仍按保守基线看待。 |
| 重建调整型 | 转型/待业/已有压力或不确定 | 当前先解决可承受周期，再验证新的收入路径。 |

标签不得作为用户数据库中的画像标签供广告、推荐或外部接口使用。

#### 2.4.3 “怎么算的”透明说明

结果页放一个可展开抽屉，不要求用户理解折现模型。文案必须说清：

1. 这是以当前税后收入区间、工作方式和你对近期变化的判断推演出的十年收入范围；
2. 它没有计算房子、存款、债务、伴侣收入、投资收益或生活支出；
3. 它不会预测一个人的真实能力、职业前景或幸福程度；
4. 修改任一回答后，结果会重新在本机计算；
5. 完整计算方法、默认参数版本和生效日期可在“规则说明”中查看。

## 3. 进阶版：登录后才开启的财务实验室

### 3.1 进入条件与价值交换

**登录不是为拿到基础结果，而是为保存和做更私密、更复杂的计算。** 用户点击进阶入口后，用以下页面解释价值：

| 登录后获得 | 需要用户补充 | 默认隐私承诺 |
| --- | --- | --- |
| 保存多次测算和行动计划 | 可选微信授权身份 | 不读取昵称、手机号之外的无关信息 |
| 安全垫与现金流缺口 | 基本支出、负债、应急金 | 金额默认仅本地；云同步二次确认 |
| 人生选择模拟 | 进修、转岗、还贷等计划 | 不向第三方共享或用于营销画像 |
| 私密报告 | 用户主动填写的资产负债 | 不公开排名、不生成征信分数 |

登录页有两个同等清晰的选项：`微信登录并保存` 与 `暂不登录，继续使用快速测`。不得用阻断式弹窗让用户误以为登录是必需的。

### 3.2 进阶版信息架构

注册成功后采用“任务清单 + 分模块完成”的首页，而不是一次性长表单。

```text
我的财务实验室
├── 今日概览
│   ├── 已完成：未来收入地图
│   ├── 待补充：每月基本开销
│   ├── 待补充：资产与负债（可跳过）
│   └── 下一步建议
├── 我的基础盘
│   ├── 收入与职业
│   ├── 基本支出与责任
│   ├── 资产与负债
│   └── 退休与长期保障（后续版本）
├── 我的选择
│   ├── 进修 / 转行
│   ├── 储蓄 / 提前还贷
│   └── 自定义人生事件
├── 我的报告
│   ├── 安全垫与现金流
│   ├── 三情景结果
│   └── 历史快照
└── 数据与隐私
    ├── 本地数据
    ├── 云同步开关
    ├── 导出
    └── 删除全部数据
```

### 3.3 分期能力，不要一次实现完整模型

| 进阶小版本 | 用户能力 | 最小输入 | 结果 | 上线门槛 |
| --- | --- | --- | --- | --- |
| V2.0 安全垫 | 了解撑多久 | 税后收入、基本月支出、现金/应急金、债务月供 | 可覆盖月数、未来 12 个月缺口提醒 | 计算/解释/删除数据可用 |
| V2.1 人生选择 | 比较一个计划 | 计划成本、开始时间、预期收入变化 | 基准 vs 计划的现金流差异 | 不把结果写成确定收益 |
| V2.2 完整现金流 | 看工作期内的情景 | 退休节点、收入增长、再学习成本、责任变化 | HCV 三情景与时间线 | 纯计算模块测试充分 |
| V2.3 资产负债 | 合并已有资产 | 审慎资产值、负债余额、资产计价方式 | NAV、PEV 与双计提示 | 资产法/收益法互斥校验 |
| V2.4 家庭模式 | 管理共享边界 | 归属、共同收支、共同债务 | 家庭报告或个人份额报告 | 用户确认口径并可随时改回个人模式 |

V2.0 比完整 DCF 更值得优先：它有直接行动价值、输入少、解释容易，也能验证用户是否愿意注册和保存数据。

## 4. 数据、账号和隐私实施

### 4.1 数据分级与默认存储

| 数据类型 | 示例 | V1 默认位置 | 云端策略 |
| --- | --- | --- | --- |
| 快速测草稿与结果 | 年龄段、收入区间、工作类型 | 小程序本地存储 | 不上传 |
| 分享卡 | 不含金额的标签、行动宣言 | 临时本地文件 | 生成后可删除，不上传 |
| 账号标识 | 微信 openid 的服务端映射 | 仅登录后服务端 | 不与财务明细混用作分析 |
| 财务明细 | 支出、债务、资产、计划 | 优先本地加密/受保护存储 | 仅用户主动开启同步后加密上传 |
| 产品事件 | 页面查看、完成、分享按钮点击 | 匿名聚合事件 | 不带金额、职业、年龄组合或原始答案 |

在微信小程序中，`wx.setStorageSync` 不是金融级安全仓库。因此 V1 只保存低敏的区间与短期草稿；涉及明确金额、资产和负债时，要么只在当前会话内保存，要么在用户明确同意云同步后，用服务端加密存储。上线前应由安全与隐私专业人士评估小程序平台能力及适用规则。

### 4.2 权限与授权页面

| 动作 | 是否需要登录 | 是否需要额外确认 | 用户可见说明 |
| --- | --- | --- | --- |
| 快速测与查看结果 | 否 | 否 | 数据只保留在本机 |
| 生成本地分享卡 | 否 | 否 | 卡片不含金额和个人信息 |
| 保存跨设备报告 | 是 | 是，开启云同步 | 说明保存哪些字段、目的、保留期、撤回方式 |
| 导出报告 | 是 | 是，导出前预览 | 显示将包含哪些金额和假设 |
| 删除云端数据 | 是 | 二次确认 | 删除范围、生效时间和不可恢复性 |

隐私政策、个人信息收集清单、第三方 SDK 清单、用户协议应在首发前完成并由适格人员审查。不得把“同意隐私政策”与“同意营销、画像或对外分享”打包。

### 4.3 删除、导出、留存

最少实现以下能力：

1. 匿名用户可在“设置”一键删除本机快速测草稿、结果和分享卡缓存；
2. 登录用户可导出自己的结构化数据和报告 PDF/图片预览；
3. 登录用户可删除单个报告、单个场景、全部云端数据及账号关联数据；
4. 删除操作写入不含财务内容的审计记录，并在隐私页说明预计完成时点；
5. 用户撤回云同步后，未来变更只留本机；是否删除既有云端数据必须单独选择；
6. 任何备份保留期、日志留存期和异常恢复策略都要写入运维文档，不能只存在于代码中。

### 5.3 快速测核心类型与接口

先把数据模型写进纯计算模块，UI 只负责收集和展示：

```ts
export type AgeBand = '18_24' | '25_29' | '30_34' | '35_39' | '40_49' | '50_plus'
export type IncomeBand = 'undisclosed' | 'under_5k' | '5_8k' | '8_12k' | '12_20k' | '20_35k' | '35_50k' | '50_80k' | '80k_plus'
export type WorkType = 'stable_employed' | 'employed_variable' | 'project' | 'business' | 'transition'
export type NearTermSignal = 'confirmed_up' | 'no_confirmed_change' | 'pressure' | 'unclear'
export type Goal = 'raise' | 'career_change' | 'stability' | 'learn' | 'save' | 'none'

export interface QuickProfile {
  schemaVersion: 1
  ageBand: AgeBand
  incomeBand: IncomeBand
  workType: WorkType
  nearTermSignal: NearTermSignal
  goal?: Goal
}

export interface MoneyRange { low: number; high: number }

export interface QuickResult {
  engineVersion: string
  calculatedAt: string
  tenYearIncome?: { bear: MoneyRange; base: MoneyRange; bull: MoneyRange }
  trajectory: 'steady_builder' | 'growth_breakthrough' | 'variable_operator' | 'rebuilding'
  stability: 'higher' | 'medium' | 'lower'
  actions: Array<{ id: string; title: string; rationale: string; firstStep: string }>
  explanations: string[]
  disclosures: string[]
}

export function calculateQuick(profile: QuickProfile, assumptions: QuickAssumptionSet): QuickResult
```

约束：

- `calculateQuick` 必须确定性：相同输入、相同参数版本，结果完全相同；
- 计算内核不得读取设备信息、网络、登录身份或埋点 SDK；
- 金额计算不得使用浮点累计误差作为展示依据；以“分”或整数元计算，显示时才格式化；
- 参数版本必须写进每个结果，以便以后规则变化时能解释历史报告；
- UI 不得自行计算收入结果或复制任何默认参数。

### 5.4 进阶 API（V2 以后）

仅在用户登录、明确启用云同步后提供以下资源。接口示例是实现边界，实际鉴权、幂等键、速率限制、审计和错误码需补齐。

| 方法 | 路径 | 用途 | 不应返回 |
| --- | --- | --- | --- |
| `POST` | `/v1/auth/wechat/session` | 用临时 code 建立会话 | 原始微信凭据 |
| `GET` | `/v1/assumptions/current` | 获取签名的参数版本 | 其他用户数据 |
| `POST` | `/v1/reports` | 保存已加密的报告快照 | 未脱敏的服务器内部错误 |
| `GET` | `/v1/reports` | 列出当前用户报告摘要 | 财务明细默认全量 |
| `GET` | `/v1/reports/:id` | 获取一个报告 | 不属于当前会话的报告 |
| `DELETE` | `/v1/reports/:id` | 删除报告 | 删除后已无效的敏感内容 |
| `POST` | `/v1/privacy/export` | 创建导出任务 | 直接暴露下载文件给未经复验会话 |
| `DELETE` | `/v1/privacy/account-data` | 删除账号关联数据 | 他人数据或模糊删除结果 |

数据库至少将认证身份表、加密财务负载、报告索引、参数版本、审计日志分开。数据库、对象存储、备份、监控和日志均不得记录原始收入、资产、债务或报告 JSON。

### 5.5 参数和内容治理

算法参数、行动文案、免责声明不可硬编码在页面中。建立内容/参数发布流程：

```text
提出改动 → 产品/研究校验 → 财务与合规复核 → 版本编号 → 测试环境回归
→ 灰度发布 → 观察完成率/投诉/误解反馈 → 全量或回滚
```

每个参数包包含：`version`、`effectiveDate`、适用产品版本、变更摘要、制定依据、审阅人、回滚版本。任何影响结果金额的改动都要新增版本，禁止静默改写历史报告。

## 6. 分阶段开发步骤与验收标准

以下顺序按依赖关系安排。以一人全职开发估算，V1 通常需要 3–5 周；时间取决于设计、测试和小程序审核准备，不应把日历承诺当作固定工期。

### 阶段 0：确认边界与原型（约 3–5 个工作日）

**目标**：在写业务代码前固定第一版只做什么、不做什么。

1. 将本方案第 1、2 节评审为 V1 范围；明确 V1 不做登录、不做云端财务数据、不做资产负债、不做完整 DCF；
2. 确认品牌名、首屏标题、结果命名和免责声明；
3. 画 5 个低保真页面：落地、问答、结果、行动、分享；
4. 准备至少 8 个匿名用户案例，覆盖稳定受雇、绩效岗位、自由职业、自营、转型/待业、拒绝填收入；
5. 和 5–8 位目标用户做纸面/可点击原型测试，观察是否理解结果与愿意分享；
6. 记录每个案例的预期输入、预期标签、是否显示金额、推荐行动和不应出现的误导文案。

**验收**：80% 以上测试者能复述“它测的是未来职业收入范围，不是给人定价”；没有人被要求登录才能首次看到结果；形成已确认的页面流程和案例表。

### 阶段 1：工程底座与质量门槛（约 2–3 个工作日）

1. 初始化 TypeScript 小程序工程、代码格式化、lint、单元测试和提交前检查；
2. 建立 `packages/engine`，确保它可以在 Node 测试环境独立运行；
3. 建立类型、参数版本格式、内容 JSON 格式和本地草稿 schema；
4. 配置三套环境标识：开发、测试、生产；生产环境不得打印完整业务对象；
5. 建立错误边界：计算异常显示“暂时无法生成，请检查回答或重试”，不显示堆栈、不丢弃草稿；
6. 建立最小 CI：类型检查、lint、单元测试、构建小程序包。

**验收**：空工程可在微信开发者工具预览；CI 任一检查失败会阻止合并；计算模块没有对 `wx`、DOM 或网络 API 的依赖。

### 阶段 2：实现并锁定简单版计算内核（约 3–4 个工作日）

1. 编写 `IncomeBand → MoneyRange` 映射、工作状态默认参数和参数版本装载器；
2. 实现三情景十年收入计算、结果区间格式化、标签映射和行动卡选择；
3. 实现输入校验：未知枚举、缺失必填值、范围颠倒、过期 schema 都应返回可处理错误；
4. 实现“不透露收入”分支，确保结果没有金额或从推断中反推出金额；
5. 写“怎么算的”解释生成器，所有解释都从参数/输入可追溯；
6. 写单元测试和快照测试，使用阶段 0 的所有匿名案例；
7. 请非开发者逐条读结果文案，删除“高价值、低价值、领先、落后、打败”等比较性表达。

**验收**：

- 每个固定案例输出可复现，且结果落在业务预期范围；
- 三个情景始终满足 `bear.low ≤ base.low ≤ bull.low` 及对应上界；
- “不透露收入”路径不产生货币数字；
- 参数版本变化能导致预期不同的结果，但历史测试仍可按原版本复现；
- 测试覆盖计算、标签、行动选择和错误分支，不只覆盖 UI。

### 阶段 3：完成匿名快速测 UI（约 4–6 个工作日）

1. 实现落地页和“怎么算的”说明弹层；
2. 实现单题页、进度条、键盘无障碍/大字体适配、返回修改、草稿自动保存；
3. 表单选择后不立即跳转，保持 150–250ms 的明确反馈；
4. 结果页按 2.3 实现，先渲染核心结果，再渲染可展开解释和行动建议；
5. 实现修改答案后重新计算，且不生成多个无意义结果副本；
6. 实现设置页的本机数据清理；
7. 在真机检查低端机、离线、前后台切换、字体放大和横竖屏（如支持）的行为。

**验收**：从首次打开到结果不依赖网络；常规路径不超过 5 次选择操作；用户可在任意问题后返回且选择不丢失；清除本地数据后重新进入没有旧结果；所有结果页固定显示边界提示。

### 阶段 4：分享卡与裂变承接（约 2–3 个工作日）

1. 用 Canvas 生成本地图片，优先在真机验证字体、长文本、深浅模式和保存相册权限；
2. 将分享数据定义为单独的 `ShareCardModel`，代码层面不允许包含收入、年龄、职业、原始问题答案或建议理由；
3. 实现 `onShareAppMessage`，分享路径只带短邀请码/来源标记，不带结果和个人答案；
4. 实现好友承接页文案，不尝试复现分享者结果；
5. 测试生成失败、拒绝相册权限、截图分享等路径，不能阻断用户回看结果。

**验收**：对分享模型做自动字段扫描/测试，确认敏感字段无法传入；不同输入产生的分享卡均没有金额或“排名”；被分享者从链接进入可独立完成自己的测算。

### 阶段 5：埋点、灰度与内容验证（约 3–5 个工作日）

只记录必要的匿名产品事件：

```text
quick_landing_view
quick_started
quick_question_answered { questionId }
quick_completed { resultType, incomeDisclosed }
quick_action_opened { actionId }
quick_share_requested { shareMethod }
quick_upgrade_viewed
quick_upgrade_clicked
quick_local_data_cleared
```

禁止在事件属性中发送收入区间、年龄、职业、用户答案、金额、完整结果或可重新识别的组合。

步骤：

1. 先在测试环境验证事件结构和屏蔽字段；
2. 用 20–30 名种子用户灰度，收集完成率、分享点击、登录意向、误解与不适反馈；
3. 对每个掉点用户访谈/问卷时，让其自愿解释原因，不在产品内追踪财务输入；
4. 根据反馈只调整最关键的题目、文案或行动卡；参数变动须走 5.5 的版本流程；
5. 建立投诉/纠错入口，特别处理“结果像在给人打分”“金额不可信”“隐私担忧”三类反馈。

**验收**：仪表盘能回答“从哪里流失”，但不能查看任何人的财务信息；完成率、误解率和用户直接反馈达到第 2.1 节的首发门槛后再扩大流量。

### 阶段 6：V2.0 登录与安全垫（约 1–2 周）

在 V1 验证成立前不要提前做。开始后按下面顺序：

1. 编写数据流图、威胁建模、授权文案、删除/导出规格；
2. 实现微信登录、服务端会话、最小账号表和权限检查；
3. 先实现不含资产明细的“基本支出 + 现金 + 月供”安全垫模块；
4. 实现明确的云同步开关、报告快照、导出与删除；
5. 以匿名案例做计算与端到端测试；
6. 进行隐私、安全、合规和小程序审核材料复核；
7. 小范围邀请已经主动点击进阶入口的用户测试，而不是默认迁移全部 V1 用户。

**验收**：未开启同步的用户没有任何财务明细请求；用户可确认并删除其云端报告；安全垫计算能解释使用了哪些输入；进阶用户仍可回到匿名快速测，不会被绑定到强制填表路径。

## 8. 优先级与暂缓事项

### 必须先做（V1）

1. 匿名快速问答；
2. 可解释的十年职业收入三情景；
3. 中性路径标签和行动建议；
4. 不含金额的分享卡；
5. 本地草稿与一键清除；
6. 参数版本、计算测试和最小匿名埋点。

### V1 明确不做

1. 登录、云同步、付费订阅；
2. 资产、房产、股票、养老金、税社保精算；
3. 债务、家庭、伴侣资料；
4. 完整 DCF、HCV/NAV/PEV；
5. AI 自动预测职业前景；
6. 外部账户抓取；
7. 排行榜、匹配、社区、公开案例；
8. 基于分享的奖励裂变机制；在价值与隐私模型验证前，不应用红包、排名或“邀请 X 人解锁结果”来驱动分享。

### 进入下一阶段的决策门

| 观察到的信号 | 下一步 |
| --- | --- |
| 完成率高，但进阶意向低 | 优化分享与行动内容，暂缓重型财务模块 |
| 大量用户问“我能撑几个月” | 优先 V2.0 安全垫 |
| 大量用户问“转行/进修值不值” | 优先 V2.1 选择模拟 |
| 用户愿意录入资产负债且主动要求报告 | 再进入 V2.2/V2.3 完整模型 |
| 用户反复误解为身价测试 | 立即收紧命名与结果文案，暂停增长投放 |
| 隐私担忧明显 | 保持纯本地，先改善解释和删除能力，不急于登录 |
