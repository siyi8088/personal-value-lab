# 个人现金流 DCF 实验室：重构方案（v1.0）

## 0. 重构结论

产品从“未来十年收入地图”调整为：

> **个人现金流 DCF 实验室**：用企业估值的显性期、退休后现金流、终值、折现率、敏感性与反向求解框架，帮助用户看见自己的收入系统由什么构成、会在何时停止，以及一个目标需要哪些现实条件才能成立。

它是一个带有娱乐性和金融教育属性的现金流实验工具，**不衡量人的价值**。所有面向用户的核心术语必须使用“个人现金流系统”“收入系统价值”“经济安全与选择空间”，避免使用“人值多少钱”“身价”“人生 PE”等人格化表述。

这次重构不是在现有“工资增长预测”上继续加功能，而是替换产品的主问题：

| 旧问题 | 新问题 |
| --- | --- |
| 我未来十年工资会怎样增长？ | 我的收入系统由哪些有限期和退休后现金流组成？ |
| 用户主观判断未来收入 | 用户输入可解释的现金流来源、截止时间与资产计价方法 |
| 默认输出三条收入增长路径 | 默认假设劳动收入有限且不永续；终值必须有来源 |
| 传播点是职业路径标签 | 传播点是“退休后现金流占比 / 严格终值占比” |
| 高级版补充复杂财务表 | 高级版用反向 DCF 倒推目标需要满足的条件 |

---

## 1. 产品洞察：为什么这个方向更有特色

企业 DCF 的吸引力不在于一个看似精确的目标价，而在于它逼着人回答四个问题：

1. 未来现金流具体来自哪里？
2. 哪些现金流有明确截止日，哪些能在显性期之后继续存在？
3. 增长依赖什么再投资，是否可持续？
4. 若我想达到一个目标价值，现实中必须做到什么？

迁移到个人时，最有价值的反差是：**大部分人的工资是有限期现金流，而不是永续现金流。**

这不是负面评价。它只是说明“依靠本人工作时间的收入”与“退休后仍能持续产生的收入系统”在财务结构上不同。用户不需要拥有严格意义的永续终值，养老金、年金等有限退休后现金流同样具有真实价值。

因此产品需要同时保留两个指标：

| 指标 | 定义 | 为什么需要 |
| --- | --- | --- |
| **退休后现金流占比** | 退休后所有可建模现金流的现值 ÷ 个人现金流系统总现值 | 适用于有养老金、年金等绝大多数用户 |
| **严格终值占比** | 符合持续经营/独立可持续收入条件的 Gordon 终值现值 ÷ 总现值 | 保留 DCF 的终值逻辑，适用于少数具备条件的收入引擎 |

主分享指标优先使用“退休后现金流占比”；“严格终值占比”放入详情页或面向 DCF 爱好者的模式。不能为了传播性，把所有退休后收入错误地包装成永续终值。

## 2. 对企业 DCF 的个人化映射

### 2.1 三段式价值结构

```text
个人现金流系统现值（PCSV）
  = 显性工作期自由现金流现值
  + 退休后有限现金流现值
  + 严格终值现值（如符合条件）
  + 当前资产净值（如选择资产法）
```

其中：

```text
个人自由现金流（PFCF）
  = 税后劳动 / 自营收入
  + 独立持续收入的净现金流
  − 保持收入能力的必要投入
  − 基本生活与已确认家庭责任（进阶口径）
  − 支撑持续收入所需的再投资
```

必须在结果页让用户选择并看见计算口径：

1. **收入能力口径**：不扣基本生活支出，回答“我的收入系统能产生多少税后现金流”；适合作为轻量娱乐测算。
2. **可支配现金流口径**：扣除基本生活、债务与家庭刚性责任，回答“我有多少真正可选择的现金流”；仅适合进阶版。

两种口径不能在同一个总数中混用，也不能都叫“价值”。首发默认使用收入能力口径，防止要求用户首次录入过多敏感家庭信息。

### 2.2 企业 DCF 概念与个人对应

| 企业估值 | 个人现金流系统 | 产品解释 |
| --- | --- | --- |
| 显性预测期 FCFF | 工作至退休/退出节点前的 PFCF | 工资和项目收入有明确期限，不默认永续 |
| CapEx / 维护投入 | 学习、执照、工具、健康、获客、经营维护 | 保持收入能力不是免费的 |
| Growth CapEx | 产生新收入引擎的投入 | 转岗、创业、内容/版权、经营扩张等 |
| ROIC | 收入引擎回报率 | 为获得一单位持续净现金流所需本金、时间和管理投入的效率 |
| WACC | 个人风险调整折现率 `r` | 时间价值 + 收入中断 + 集中度 + 流动性等风险 |
| Terminal Value | 符合条件的持续经营/收入引擎价值 | 不是“人会永远工作” |
| EV/EBITDA 退出倍数 | 持续收入倍数 | 仅作为资产/收入引擎的交叉校验，绝不叫“人的 PE” |
| Reverse DCF | 目标价值倒推 | 从用户目标反推所需现金流条件，而不是预测命运 |

### 2.3 四类现金流，四种处理方式

| 类型 | 例子 | 显性期 | 退休后有限现金流 | 严格终值 | 关键约束 |
| --- | --- | --- | --- | --- | --- |
| 劳动收入 | 工资、奖金、项目、自由职业 | 是，至退休/合同结束 | 否 | 否 | 不得因“工作稳定”假设工资永续 |
| 规则型退休收入 | 社保养老金、企业年金、商业年金 | 按开始节点 | 是，按领取期限/生存概率 | 通常否 | 不是戈登模型；规则、资格和调整需可编辑 |
| 持续经营收入 | 已有自营业务分红、可续约版权、成熟订阅业务 | 是 | 视情况 | 条件允许 | 必须扣除维护/再投资，说明继任、竞争和衰减风险 |
| 金融/实物资产收入 | 股票、债券、基金、出租房 | 二选一 | 二选一 | 仅少数条件允许 | 与当前 NAV 互斥，严防双重计价 |

### 2.4 资产防双重计价：不可妥协的规则

资产卡必须强制选择以下其中一种方法，并在报告封面显示：

```text
资产法（NAV）
  今天的审慎可变现价值计入 PCSV
  → 不再折现该资产的全部未来利息、股息、租金或经营现金流

收益法（DCF）
  将未来独立净现金流折现计入 PCSV
  → 不再将同一资产的当前市值/NAV计入 PCSV
```

具体规则：

- **国债/定存**：不是 `g` 的来源。它是有限期票息和本金，或直接按当前净值计入 NAV；“不断滚动购买国债”不能默认变成永续增长。
- **股票/基金**：市场价格通常已经包含市场对未来增长的预期。若用市值计入 NAV，就不再把完整股息与资本增值折现；若用收益法，则不加市值。
- **出租房**：净变现价值与租金 DCF 二选一。
- **企业股权/自营业务**：公允价值与经营现金流 DCF 二选一。
- **养老金权益**：通常按有限领取期现金流计算；不可自由处置的权益不得被表述为随时可用资产。

## 3. 终值、g 与再投资：产品必须讲清的 DCF 灵魂

### 3.1 “终值”不是退休后全部收入

产品把结果分为三类，避免概念混乱：

```text
工作期现值
    工资 / 项目 / 自营劳动收入，至退休或退出节点

退休后现金流现值
    养老金 / 年金 / 明确期限的租金、版权或收益

严格终值现值
    仅来自通过准入条件的持续经营或独立收入引擎
```

分享时用“退休后现金流占比”；详情页才展示严格终值占比、终值占总值比例和敏感性。

### 3.2 严格终值的准入条件

只有同时满足以下条件，才能让用户开启 Gordon 终值：

1. 收入在工作停止后仍有独立、可持续的合同、资产或经营基础；
2. 已明确该收入未以 NAV/市值方式计入；
3. 已录入维持该收入所需的管理、维护、获客、更新或资本再投资；
4. 现金流不存在已知硬截止日；若有硬截止日，应改用有限期 DCF；
5. `r > g`；
6. `g` 不高于参数包中的长期宏观审慎上限；
7. 用户理解这是一组假设，而不是投资回报承诺。

### 3.3 自洽的个人终值公式

对满足条件的收入引擎，采用与企业 DCF 同样的再投资纪律：

```text
终期可分配现金流 FCF_(n+1)
  = 终期收入引擎的税后净营运现金流 × [1 − (g ÷ RIR)]

终值 TV_n
  = FCF_(n+1) ÷ (r − g)

终值现值 PV(TV)
  = TV_n ÷ (1 + r)^n
```

其中 `RIR`（Recurring Income Return）是“收入引擎回报率”：为维持/扩张持续净现金流所需再投资的回报效率。它是教育性近似，不应伪装成精确个人 ROIC。

产品校验：

- `r <= g`：阻止计算；
- `g > RIR`：阻止计算，因再投资率会超过 100%；
- 再投资率 `g / RIR` 超过 50%：高亮提示；
- 严格终值占比超过 35%：提醒检查假设；超过 50%：标记为“高终值依赖，不适合单点决策”；
- 将工资选择为永续：阻止；
- 已按 NAV 计入的资产再启用终值：阻止。

### 3.4 用户可读的解释

不要问“你的 g 是多少”。先问收入的商业事实，再由系统给出可编辑建议范围：

> 这项收入如果你停止主要工作后，仍能否在不出售本金的情况下持续产生？

> 为了让它维持或增长，你每年还需要投入多少资金、时间或管理？

> 它的增长来自合同提价、客户续约、租金调整、再投资，还是只是你的期待？

只有用户回答后，才呈现 `g`、`r`、再投资率与敏感性矩阵。初版 `g` 应默认关闭或为 0，不应默认正增长。

## 4. 产品体验：两层但围绕同一 DCF 主线

### 4.1 轻量版：我的现金流结构图

目标：用户在 3–5 分钟内获得一个有 DCF 味道、可分享、但不要求资产明细的结果。

#### 输入

1. 年龄段与预计主要工作到几岁；
2. 当前税后年收入区间；
3. 当前收入类型：稳定受雇 / 绩效 / 项目 / 自营 / 转型；
4. 是否已有退休后收入来源：暂无 / 养老金或年金 / 租金或版权 / 经营分红 / 其他；
5. 该来源每年大概净现金流：区间或“不方便说”；
6. 是否有已确认的短期收入变化：仅影响前两年；
7. 可选：选择“收入能力口径”或暂不填支出。

所有金额支持区间与跳过。轻量版不要求用户填写股票、房产、负债、伴侣或精确单位信息。

#### 结果

```text
你的个人现金流结构图

工作期现金流现值         68%
退休后现金流现值         24%
严格终值现值              8%

退休后现金流占比：32%
严格终值占比：8%
```

如果用户没有退休后来源，不展示“0 分”的羞耻感，而展示：

> 目前你的收入系统主要依赖工作期现金流。退休后收入尚未纳入模型；这在当前阶段很常见。

轻量版不显示“个人总价值”的单一大字，不进行人群比较。若显示金额，使用“在当前假设下的收入系统现值约为”并放在第二层；首屏优先展示结构和现金流停止节点。

#### 分享卡

默认不显示金额、年龄、职业、资产或家庭信息。可选文案：

> 我测了我的退休后现金流占比。\n不是我的身价，是我的收入系统能走多远。

或：

> 我的严格终值占比是 0%。\n原来我现在主要靠自己持续上班。 

后一条只由用户主动选择，不自动生成，不使用焦虑或羞耻文案驱动转发。

### 4.2 进阶版：个人现金流 DCF 底表

登录后以模块化清单收集信息，不强迫一次填写完整：

```text
收入系统
├── 工作期收入与退休节点
├── 必要职业维护 / 再学习投入
├── 基本支出与家庭责任（切换可支配现金流口径）
├── 退休后有限现金流：养老金、年金、期限型收入
├── 持续收入引擎：经营、租金、版权、订阅等
├── 资产与负债：资产法 / 收益法二选一
└── 假设实验室：r、g、再投资、期限、情景
```

进阶报告应展示：

1. 显性工作期、退休后有限期、严格终值、NAV 的瀑布图；
2. 每项收入的开始、结束、计价方法、风险和再投资说明；
3. `r × g` 敏感性矩阵，仅在严格终值存在时显示；
4. 终值占比与隐含持续收入倍数；
5. 双计检查、数据缺失和高不确定性提示；
6. 可解释的行动实验：进修、转岗、储蓄、建立收入引擎、提前还债等。

## 5. 高级功能：目标价值倒推（个人版反向 DCF）

### 5.1 功能定位

这不是传统意义上“市场价格隐含预期”的反向 DCF，因为个人没有一个公开市场成交价。它是同一套数学和反向工程思维在个人规划中的应用：

> **把用户设定的目标现金流系统现值作为终点，倒推在一组明确、保守假设下，需要满足哪些现金流条件。**

对外功能名建议使用：

- **目标价值倒推**
- **我的现金流目标需要什么条件？**
- **反向 DCF 实验室**（面向了解估值概念的高级用户）

不要叫“你必须赚多少钱”，不要暗示一个数是人生成功门槛。

### 5.2 输入、冻结常数与可求解变量

先冻结不应被求解器随意扭动的参数：

| 冻结参数 | 来源 | 原则 |
| --- | --- | --- |
| 当前可计入 NAV | 用户确认的资产法项目减负债 | 不把未来现金流再计入 |
| 当前工作至退休期限 | 用户设定 | 可做情景，但不能被算法暗改 |
| 退休后有限现金流 | 用户输入养老金/年金规则 | 与严格终值分开 |
| 折现率 `r` | 系统建议 + 用户编辑 | 显示风险构成与影响 |
| 长期增长 `g` | 仅合格收入引擎可用 | 受 `r > g`、宏观上限和再投资约束 |
| 收入引擎回报率 `RIR` | 用户/系统情景 | 决定支撑增长的再投资成本 |

用户只选择**一个主要未知数**进行求解，防止无限多解：

1. 目标退休后每年需要多少持续净现金流？
2. 若没有持续收入引擎，工作期年收入需要达到什么水平？
3. 以当前收入路径不变，需要额外积累多少可计入 NAV 的资产？
4. 若每月新增固定储蓄，目标大约需要几年才能达到？

### 5.3 核心倒推公式

设用户目标为 `V*`，现有可解释价值由以下部分构成：

```text
V_known
  = PV(工作期现金流)
  + PV(退休后有限现金流)
  + PV(现有合格终值)
  + NAV

价值缺口 Gap
  = max(0, V* − V_known)
```

若用户选择“补足退休后持续收入”，并将目标收入引擎开始时间设为 `n` 年后：

```text
需要的第 n+1 年终期可分配现金流
  = Gap × (1 + r)^n × (r − g)

需要的终期税后净营运现金流
  = 所需可分配现金流 ÷ [1 − (g ÷ RIR)]
```

输出的不是一句“你要每年赚 X”，而是：

```text
在当前假设下，目标缺口为……

若在退休前建立一项持续收入引擎：
退休后首年需要约……的税后净现金流。
为维持设定的 g，需要把其中约……继续投入维护与增长。
这只是数学条件，不代表可行性或推荐路径。
```

若用户选择“以工作期收入弥补”：

```text
所需额外年 PFCF
  = Gap ÷ Σ[1 ÷ (1 + r)^t],  t = 1..剩余工作年限
```

结果应同时说明：工资是有限期现金流，因此同样的目标，用工作收入补足通常需要更高的年度金额；这不是用户不够努力，而是有限期与持续现金流的数学差异。

### 5.4 三条路径，而非单一军令状

反向 DCF 页面不能只给一个高得吓人的工资数字。它应显示等价值路径卡：

| 路径 | 求解变量 | 用户看到的内容 | 适用边界 |
| --- | --- | --- | --- |
| 工作期路径 | 工作年限内的额外年 PFCF | 目标需多出的年现金流与持续年数 | 有限期，不产生严格终值 |
| 持续收入路径 | 退休后首年持续净现金流 | 需要的收入引擎规模、g、再投资率 | 必须通过严格终值准入 |
| 资产积累路径 | 额外 NAV / 定期储蓄 | 目标时点需积累的资产值和储蓄路径 | 不把资产收益重复计入 |

用户可以比较：同一个目标，是多工作五年、提高可支配收入、积累资产，还是建立可持续经营收入，分别需要什么条件。工具不能替用户判断哪种人生更好。

### 5.5 反向 DCF 的“现实校验”

第 09 节的精髓是把数学结果放回现实，检验隐含目标是否合理。个人版同样需要这一页：

```text
目标：个人现金流系统现值 500 万
模型倒推：退休后首年需持续净现金流 12 万 / 年

现实校验：
□ 这项收入来自什么？
□ 是否有合同、客户、资产或制度基础？
□ 需要多少本金、时间和维护投入？
□ 是否已经被 NAV 计入？
□ 如果 g 从 1.5% 回到 0%，结果还成立吗？
□ 如果收入延迟 3 年才开始，缺口会多大？
```

这页的结论可以是“条件较苛刻”“需要验证”“当前信息不足”，而不是只鼓励用户调高 `g` 或调低 `r`。产品的教育价值正来自让不现实的数学条件显形。

## 6. 数据模型与计算模块重构

### 6.1 核心类型

```ts
type ValuationMethod = 'nav' | 'cashflow'
type IncomeKind = 'labor' | 'pension' | 'annuity' | 'business' | 'rental' | 'royalty' | 'investment'

interface IncomeStream {
  id: string
  kind: IncomeKind
  annualAfterTaxCashFlow: number
  startYear: number
  endYear?: number                 // 缺失不等于允许终值，仍需资格校验
  isIndependentAfterRetirement: boolean
  maintenanceCost: number
  valuationMethod?: ValuationMethod
  supportsTerminalValue: boolean
  recurringIncomeReturn?: number   // RIR
  longTermGrowthRate?: number      // g
}

interface Asset {
  id: string
  category: 'cash' | 'bond' | 'equity_fund' | 'property' | 'business_equity' | 'other'
  conservativeValue: number
  valuationMethod: ValuationMethod
  linkedIncomeStreamIds: string[]
}

interface PersonalDcfInput {
  currentAge: number
  retirementAge: number
  annualLaborIncomeAfterTax: number
  annualIncomeMaintenanceCost: number
  discountRate: number
  incomeStreams: IncomeStream[]
  assets: Asset[]
  liabilities: Array<{ balance: number; includedInCashFlow: boolean }>
  basis: 'income_capacity' | 'disposable_cashflow'
}
```

### 6.2 计算顺序

1. 校验退休年龄、金额范围、`r > g` 和收入流开始/结束年份；
2. 将劳动收入生成为当前年龄至退休前的有限现金流；默认真实增长率为 0，短期已确认变化只影响前两年；
3. 计算养老金、年金和其他有明确结束日收入的有限期现值；
4. 对每个请求严格终值的收入流做准入和再投资校验；
5. 计算合格终值并折现；
6. 以 NAV 方法计入资产，并阻止同一资产关联收入流的 DCF 计入；
7. 扣减负债余额，检查是否已在现金流中重复扣减本金；
8. 输出总值、结构占比、退休后现金流占比、严格终值占比、风险提示、计算解释；
9. 进阶版才计算敏感性矩阵与目标价值倒推。

### 6.3 必须写入单元测试的规则

- 纯劳动收入退休后严格终值为 0；
- 默认劳动收入长期真实增长为 0；
- 养老金有价值，但不自动被算作 Gordon 终值；
- 同一股票/房产/股权选择 NAV 与 DCF 会报错；
- 国债不能直接成为永续 `g` 来源；
- `r <= g`、`g > RIR`、再投资率超过 100% 必须阻止；
- 反向求解满足“正向重算后回到目标值”的闭环误差；
- 未提供严格终值资格时，反向求解不应要求用户虚构被动收入；
- 分享模型不能包含任何金额、资产、债务、年龄或收入流信息。

## 7. 页面与交互重构

### 7.1 首发页面

```text
落地页：你的收入系统能走多远？
  ↓
边界说明：估算现金流，不衡量人
  ↓
轻量输入：工作期 + 退休后来源
  ↓
结果：现金流结构图 + 退休后现金流占比
  ↓                    ↘
分享卡                    继续补全我的 DCF 底表
                           ↓
                     微信登录（保存、进阶计算）
```

### 7.2 结果页的首屏结构

1. 标题：`你的收入系统，主要依靠什么？`
2. 环图/堆叠条：工作期、退休后有限期、严格终值、NAV；
3. 主指标：退休后现金流占比；
4. 第二指标：严格终值占比（没有则解释“当前未纳入严格终值”）；
5. 一句解释：`工资收入会在预计退休节点结束；退休后现金流是否存在，取决于你已录入的规则型收入与独立收入引擎。`
6. 一张行动卡：不是“提高身价”，而是“补充养老金信息”“检查一项资产是否重复计价”“验证持续收入的维护成本”。

### 7.3 高级版结果页

导航：`结构` / `底表` / `敏感性` / `目标倒推` / `数据与隐私`。

“目标倒推”入口仅在用户拥有完整基础输入、并主动设定目标后开放。显示教育引导：

> 倒推展示的是一组数学条件。它不承诺收入、投资回报或实现概率，也不要求你选择其中任意路径。

## 8. 传播、文案与风险边界

### 8.1 推荐传播文案

- `我测了我的退休后现金流占比。不是身价，是收入系统能走多远。`
- `工资停止以后，我的现金流还剩多少？`
- `你的退休后现金流占比是多少？`
- `终值不是每个人都需要有；看清它从哪里来更重要。`

### 8.2 禁止文案

- “你的身价超过了多少人”；
- “职业 X 比职业 Y 更值钱”；
- “提高 g，让你价值暴涨”；
- “买入某资产即可获得终值”；
- “被动收入越高，人越成功”；
- “达到目标价值才能实现财务自由”。

### 8.3 结果固定披露

> 这是依据用户假设生成的现金流教育模型，不衡量人的价值，不构成投资、税务、法律、保险或职业建议。终值和增长率对结果高度敏感，尤其不应被视为保证收入。

## 9. 实施路线图

### Phase A：先重构产品原型与计算内核

1. 停止把现有“未来收入地图”的十年工资增长计算作为产品核心；
2. 设计新的收入流、资产、计价方法和终值资格数据模型；
3. 实现纯计算模块：有限劳动期、有限退休后收入、严格终值、NAV 与防双计校验；
4. 用至少 10 个匿名案例手算并写测试：纯工资、养老金、年金、出租房资产法、出租房收益法、股票 NAV、自营业务、版权衰减、负债、无终值；
5. 完成“结构图”低保真原型与 5–8 人可用性测试。

**验收**：测试者能区分退休后有限现金流与严格终值；没有人认为股票市值和股息可以同时全额相加；纯工资案例不会产生终值。

### Phase B：轻量版重新上线

1. 将现有五题问答换成工作期 + 退休后来源的轻量输入；
2. 首屏结果改为结构图和退休后现金流占比；
3. 重新设计不含金额的分享卡；
4. 保持匿名、本地优先、无需登录；
5. 埋点仅记录完成与分享动作，不记录收入、资产、终值或结果金额。

**验收**：用户能在 5 分钟内完成，理解“不是人的价值”，且分享卡没有金额与敏感信息。

### Phase C：登录后的 DCF 底表

1. 建立渐进式模块录入、云同步授权、删除和导出；
2. 实现可支配现金流口径、资产负债、有限养老金/年金、持续收入引擎；
3. 实现终值资格校验、`r × g` 矩阵、隐含持续收入倍数；
4. 通过财务规划、隐私与合规评审后灰度发布。

### Phase D：目标价值倒推

1. 先实现单变量求解器与正反闭环测试；
2. 支持工作期、持续收入、资产积累三条等价值路径；
3. 实现现实校验清单、延迟/`g=0`/更高折现率压力测试；
4. 禁止将倒推结果用于广告定向、借贷推荐或用户排名。

## 10. 当前代码的处置

当前仓库中的“未来收入地图”是已完成的交互原型，但其主计算逻辑仍是旧方向。重构时应保留以下可复用部分：

- 原生微信小程序工程、离线本地存储与隐私设置；
- 结果、行动和不含敏感信息的分享卡页面骨架；
- 独立纯计算模块与 Node 单元测试方式；
- 匿名优先、无登录前不上传数据的架构原则。

应替换以下部分：

- 年龄、收入、工作状态、短期信号到十年收入的旧映射；
- “收入路径类型”结果标签；
- 默认十年工资估算结果页；
- 仅围绕工资收入的行动卡。

重构后的首个可发布版本，以“退休后现金流占比”而非“收入增长预测”作为主结果，以“严格终值占比”作为可展开的 DCF 深度指标。
